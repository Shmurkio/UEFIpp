# x64 architecture reference

`UEFIpp::Architecture::X64` models CPU state and x64 instructions and supplies encoding, assembly, decoding, formatting, disassembly, and unwinding.

Focused umbrellas: `UEFIpp/Architecture/Architecture.hpp` and `UEFIpp/Architecture/X64/X64.hpp`.

For end-to-end examples, read [x64 assembly, disassembly, and unwinding](../guides/x64-code.md).

## CPU and common registers

`Cpu` exposes control-register reads/writes, RFLAGS/RSP/TSC, CPUID, write-protect save/disable/restore, interrupt state save/restore, halt, and pause.

`CpuidResult` holds EAX, EBX, ECX, and EDX. Query a leaf/subleaf through `Cpu::Cpuid` before relying on optional instructions.

Typed bit helpers cover:

- `Cr0`, `Cr3`, and `Cr4`;
- `Rflags`;
- `Efer`;
- `SegmentSelector`.

They name masks and extract fields such as CR3 address and I/O privilege level. The underlying register value remains a 64-bit `Register`.

`CpuRandom` wraps 16/32/64-bit RDRAND and RDSEED. Calls return `Bool`; retry/fallback policy belongs to the caller. Confirm CPUID support before invoking the corresponding instruction.

`Msr` reads/writes modeled MSR indices and supplies convenience calls for APIC base, TSC deadline, EFER, FS/GS base, and kernel GS base. `FeatureControlMsr` and `PatMsr` decode selected fields.

These are privileged operations. Incorrect writes can fault or corrupt platform state.

## Instruction model

### Registers

`InstructionSet::Register` wraps `RegisterId` and exposes validity, register class, width for a machine mode, root register, and name. `RegisterSet` is a fixed bitset-like collection with add/remove/contains/clear.

Named register constants span general-purpose, x87/MMX, XMM/YMM/ZMM, tile, flags/IP, segment/table, control/debug, mask, bound, and special registers. Use the constants such as `Rax`, `Xmm0`, or `Cr3` rather than raw IDs.

### Mnemonics and attributes

`Mnemonic` identifies modeled instructions. `MnemonicCount` describes the enum table size.

Classification enums include instruction category, ISA set/extension, physical encoding, control-flow type, and instruction-attribute flags.

### Operands

`Operand` can hold a register, memory operand, far pointer, or immediate. Decoded metadata records visibility, read/write access, encoding field, width, element type, and element count.

Supporting types include `ImmediateOperand`, `MemoryOperand`, `PointerOperand`, and enums for operand type/visibility/access/encoding and memory/element type.

Convenience constructors are described in the [x64 guide](../guides/x64-code.md#build-an-instruction).

### Encoding options

`EncodingOptions` controls allowed encodings, branch/address/operand size hints, prefixes, and EVEX/MVEX options. Supporting enums cover encodable encodings, branch type/width, size hints, prefix type, masking, broadcast, rounding, swizzle, and conversion modes.

Leave options at defaults unless the exact encoding matters. Over-constraining options can turn an otherwise encodable instruction into `EncodeError`.

### Decoded instructions

`DecodedInstruction` contains high-level semantics plus raw encoding detail. Supporting records describe CPU flag access, vector encoding, legacy prefixes, REX/XOP/VEX/EVEX/MVEX, ModRM, SIB, displacement, and immediate fields.

## Encoding and assembly

`Encoder` turns one modeled `Instruction` into encoded bytes and returns `Expected<…, EncodeError>`.

`Program` owns sections, nodes, and label state. `Section` owns its name and nodes. `Node` represents instruction, label, data, or alignment entries. `Label`, `SectionId`, `Fixup`, and `Relocation` provide stable references and final-layout metadata.

`Assembler` is the high-level facade. It exposes common instruction helpers, generic `Emit`, section management, labels, data/alignment, and `Assemble`.

`CodeBuffer` owns generated bytes. `AssembledCode` combines bytes, section layout, relocation records, and base address.

Error enums distinguish instruction encoding failure from program-level assembly failure such as invalid arguments, allocation, invalid/unbound labels, section issues, overflow, and internal errors.

## Decoding and disassembly

`Decoder` decodes one instruction from a byte span or from `MemoryView`. Configuration is a `MachineMode` and `StackWidth`.

`InstructionRange` lazily iterates instructions from memory and tracks a decode-at error. Check `Error()` after or during iteration if complete traversal is required.

`Disassembler` materializes a `Disassembly` containing a vector of decoded instructions, base address, and total byte size.

`Formatter` renders decoded instructions in Intel or AT&T style. `Format` allocates; `FormatTo` returns a view into caller storage.

Decode/format/disassembly error types retain the correct layer of failure, including detailed memory-backed decode errors.

## Unwinding

`Unwind::Context` models the x64 register context needed by the unwinder. `Unwinder` validates a mapped PE image, indexes runtime functions, and performs virtual unwinding.

`RuntimeFunctionRange` exposes bounds and containment. `Frame` contains the caller context and return-address slot. Failures use `UnwindError`.

The implementation targets supported x64 PE unwind information. Unsupported versions, operations, or registers return an error rather than silently fabricating state.
